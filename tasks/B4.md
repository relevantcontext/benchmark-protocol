# B4 — Scale + loading feedback

## Task (delivered verbatim, identical to every framework arm)

> The application now runs on its full production dataset:
> 200 customers and 5,000 invoices. Every existing behavior must hold
> at this size.
>
> - All existing functionality works correctly: search, column
>   sorting, pagination, the inline status toggle, the app-wide
>   freshness guarantee, and the global quick-search overlay.
> - Interactions remain responsive at this data size: typing in
>   search, changing sort, changing pages, and toggling status feel
>   immediate, and no interaction freezes or blocks the page.
> - From a cold load, the app never shows a blank or frozen screen:
>   loading progress is visibly indicated until the page is
>   interactive.
> - The mobile card layout holds the same guarantees.

   hosted.

   enterprise-fixture baselines.
3. Cold load: visible determinate progress until interactive; no blank
   or frozen frame. Both sides.
4. Quick-search broad query at scale behaves (truncation/caps
   acceptable if communicated in the UI).
5. Mobile layout holds.
6. Production builds pass; both sides deployed against re-leveled
   scale branches; branch md5s recorded.
