# P2-1 — Spreadsheet-grade bulk editing

## Task (delivered verbatim, identical to every framework arm)

> The invoices table becomes bulk-editable.
>
> - The amount, date, and status cells of each row are editable in
>   place: clicking a cell (or pressing Enter on it) starts editing;
>   Escape cancels the edit; committing a change marks the row as
>   edited rather than saving immediately.
> - A visible cell cursor moves with the arrow keys; Enter begins
>   editing the cursor's cell. Rows can be range-selected
>   (shift-click or shift-arrows), and a selected range's status can
>   be set to paid or pending in one action.
> - Undo and redo (Ctrl/Cmd-Z, Shift-Ctrl/Cmd-Z) walk the full local
>   edit history, including bulk actions.
> - While there are unsaved edits, a save bar shows how many invoices
>   are edited, with Save All persisting every edit in one batch and
>   Discard reverting all of them. After saving, every surface of the
>   app reflects the new values immediately (the existing freshness
>   guarantee).
> - All of this composes with the existing search, sorting, and
>   pagination — and keeps working while live payment events arrive:
>   an arriving external event must never clobber an unsaved local
>   edit, and saving must not lose external changes that arrived on
>   OTHER invoices meanwhile.

## Acceptance (verified by the harness, not the building agent)

1. Cell edit (amount, date, status) via mouse and keyboard; Escape
   cancels; edited rows visibly marked; nothing persisted before Save.
2. Cursor + shift-range selection + one-action bulk status set.
3. Undo/redo walks single AND bulk edits correctly, in order.
4. Save All persists the batch (DB-verified); Discard reverts;
   post-save freshness on dashboard cards within the guarantee.
5. Concurrency: with live events running, an unsaved edited row keeps
   its local values on screen; after Save, both the saved edits AND
   external changes to other invoices are present (DB + UI).
6. Search/sort/pagination compose; B-round spot checks pass;
   production builds pass.
7. Harness metrics: boundary-sprawl counts recorded for both sides;
   dependency delta recorded with sanctioned tags.
