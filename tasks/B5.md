# B5 — Real-time payments

## Task (delivered verbatim, identical to every framework arm)

> Payments now arrive in real time.
>
> - While a user is signed in, payment activity occurs continuously:
>   every few seconds an outstanding invoice gets paid, and
>   occasionally a new invoice arrives. Events are simulated by the
>   application's own API tier — no third-party service — and every
>   event is REAL: it is persisted, so a reload shows exactly the
>   state the events produced.
> - The dashboard gains a live activity feed showing each event as it
>   happens — who, what, amount, when — newest first, updating without
>   any user action.
> - Every surface showing invoice-derived data — the dashboard cards,
>   the invoices table, pagination counts, sorted order, and
>   quick-search results — reflects each event within a couple of
>   seconds of it happening, with no manual refresh, and WITHOUT
>   disturbing what the user is doing: current search, sort, page, an
>   open quick-search overlay, and in-flight status toggles all keep
>   working correctly while events arrive.
> - The stream stops when the user signs out or leaves.

## Acceptance (verified by the harness, not the building agent)

1. Signed in on the dashboard: the activity feed populates on its own;
   dashboard cards move in exact accordance with the events shown.
2. On the invoices page mid-task (search + sort + page 2 active):
   events arrive and the visible state stays coherent — user's
   search/sort/page preserved; counts/order update where they should.
3. A user toggle issued WHILE events are arriving lands correctly
   (optimistic feedback, correct final state) — the concurrent-
   mutations test.
4. Reload after a burst: state matches what the feed showed
   (persistence).
5. Sign-out (or tab close) ends the stream server-side.
6. B1–B4 spot-checks pass; production builds pass.
7. Hosted: the same behaviors on the deployed sites — the round's
   deploy asymmetry is recorded, and if hosted delivery proves
   infra-dominated, the revert clause is evaluated rather than papered
   over.
