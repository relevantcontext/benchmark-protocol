# B1 — Column sorting

## Task (delivered verbatim, identical to every framework arm)

> Add column sorting to the invoices table.
>
> - The Customer, Amount, Date, and Status columns are sortable.
> - Clicking a column header sorts by that column; clicking the same
>   header again reverses the direction. The active column and direction
>   are visibly indicated.
> - Sort state persists in the URL: opening a shared link applies the
>   same sort, and back/forward navigation restores prior sort states.
> - Sorting composes with the existing search and pagination: changing
>   the sort keeps the current search query and returns to the first
>   page; changing pages keeps the sort.
> - With no sort in the URL, the existing default order (newest first)
>   is unchanged.
> - Both the desktop table layout and the mobile card layout present the
>   sorted order.

## Acceptance (verified by the harness, not the building agent)

1. Each of the four columns sorts, both directions, indicator visible.
2. URL round-trips: copy URL → new tab → same sort; back/forward
   restores prior sort states.
3. Compose: search + sort + paginate in every order; sort change resets
   to page 1 and keeps query; page change keeps sort.
4. No sort param → order identical to pre-B1 (date DESC, id DESC).
5. Mobile/card layout shows the same order.
6. Production build passes; no regression in existing behavior.
